# Graph XAI 의료진용 보고서 개선 작업지시서

## 1. 작업 대상

저장소:

```text
https://github.com/didtjr5080/Alzheimer-s-Dagnosis-to-Xai
```

현재 Graph XAI 확장 기능에서 생성된 다음 유형의 보고서를 의료진이 쉽게 이해할 수 있도록 개선하세요.

```text
Graph XAI 모델 출력 민감도 분석 보고서
소프트웨어 버전: 0.2.0
분류 범주: CN / MCI / AD
현재 구성: CAM, 3×3 구역 분석, zero/mean/blur 마스킹,
          민감도 순위, 안정성 지표, Graph XAI, PDF 보고서
```

## 2. 핵심 목표

현재의 기술적 분석 기능과 수치 계산은 보존하면서 보고서를 다음 두 계층으로 분리하세요.

1. **의료진용 요약본**: 핵심 결과를 2~3페이지 안에서 빠르게 이해
2. **연구자용 기술 부록**: 모델·통계·재현·테스트 정보를 상세하게 제공

의료진용 본문은 다음 순서로 답해야 합니다.

1. 모델이 무엇으로 예측했는가?
2. 모델 출력값은 얼마인가?
3. 영상의 어느 위치 변화에 모델이 민감했는가?
4. 이 설명 결과는 일관적인가?
5. 어디까지 해석할 수 있고, 무엇을 의미하지 않는가?

## 3. 파일 보호 및 수정 범위

### 수정 금지

Graph XAI 구현 이전부터 존재한 원본 프로젝트 파일은 수정하지 마세요.

- 기존 `app.py`
- 기존 학습·추론·전처리 코드
- 기존 모델·임베딩·결과 파일
- 기존 README와 의존성 파일
- 사용자의 기존 Git 변경사항

### 수정 허용

실제로 사용 중인 Graph XAI 확장 폴더 내부의 보고서 생성, UI, 시각화, 테스트, 문서 파일만 수정할 수 있습니다.

```text
graph_xai_extension/
```

여러 확장 폴더가 있으면 보고서 ID, 소프트웨어 버전, 파일 구조를 확인해 실제 실행에 사용된 폴더를 식별하세요. 확실하지 않으면 임의로 선택하지 말고 보고하세요.

기존 보고서와 결과 파일을 덮어쓰지 말고 새로운 실행 ID로 저장하세요.

## 5. 보고서 출력 모드

보고서 생성기에 다음 모드를 추가하세요.

```text
clinical_summary
technical_full
combined
```

### `clinical_summary`

- 의료진용 2~3페이지 요약본
- 쉬운 한국어 중심
- 핵심 수치와 그림만 표시
- 기술 메타데이터와 세부 통계 제외

### `technical_full`

- 연구자·개발자용 기술 보고서
- 기존 분석 수치와 재현 정보 보존
- 클래스 매핑·통계·테스트·Git 정보 포함

### `combined`

- 앞부분은 의료진용 요약
- 뒷부분은 `기술 부록`
- PDF 북마크 또는 명확한 구분 페이지 제공

기본 출력 모드는 `combined`로 하되 UI에서 선택 가능하게 하세요.

## 6. 의료진용 1페이지 구성

첫 페이지는 기술 메타데이터가 아니라 핵심 결과로 시작하세요.

### 상단 제목

```text
AI MRI 분석 요약 - 연구용
```

`진단 보고서`, `판단 보고서`, `임상 결과`라는 표현은 사용하지 마세요.

### 핵심 결과 카드

다음 네 항목을 큰 글씨로 표시하세요.

```text
모델 예측 범주
해당 범주의 모델 출력값
출력 변화가 가장 컸던 영상 위치
설명 결과의 일관성
```

현재 사례의 표현 예시:

```text
모델 예측 범주: MCI
MCI 모델 출력값: 78.92%
가장 민감하게 반응한 위치: 영상 중앙부
설명 결과의 일관성: 낮음 - 가림 방식에 따라 일부 결과가 달라짐
```

반드시 다음 문구를 출력값 가까이에 표시하세요.

```text
이 수치는 실제 MCI 가능성, 진단 확률 또는 모델 정확도를 의미하지 않습니다.
```

### 자동 요약 문장

수치에 맞춰 다음 구조로 자동 생성하세요.

```text
AI 모델은 입력 영상을 {예측 범주} 범주로 분류했으며,
해당 범주의 모델 출력값은 {출력값}%였습니다.
{대표 마스킹 방식}으로 영상의 {가장 민감한 위치}를 처리했을 때
모델 출력값이 {전}%에서 {후}%로 변했습니다.
마스킹 방식 간 설명 일관성은 {안정성}으로 평가됐습니다.
```

문장이 지나치게 길어지지 않게 3~4문장으로 제한하세요.

## 7. 의료진용 2페이지 구성

시각적 설명을 중심으로 구성하세요.

다음 네 이미지를 같은 방향과 유사한 크기로 배치하세요.

1. 원본 MRI
2. 모델 반응 지도
3. MRI와 모델 반응 지도 중첩
4. 모델 출력 변화가 가장 컸던 구역

그림 설명 예시:

```text
색이 강하게 표시된 부분은 모델 계산에 상대적으로 많이 반영된 위치입니다.
색상은 병변의 존재, 질환의 심각도 또는 조직 손상을 의미하지 않습니다.
```

마스킹 전·후 영상에는 다음을 함께 표시하세요.

```text
처리 전 모델 출력값
처리 후 모델 출력값
변화량
적용한 처리 방식
```

## 8. 의료진용 3페이지 구성

복잡한 전체 통계표 대신 중요한 결과만 표시하세요.

### 주요 변화 요약

최대 세 항목만 본문에 표시하세요.

| 구분 | 영상 위치 | 모델 출력 변화 | 쉬운 설명 |
|---|---|---:|---|
| 가장 큰 감소 | 중앙부 | 78.92% → 22.26% | 이 위치를 처리했을 때 출력값이 크게 낮아짐 |
| 두 번째 감소 | 아래 중앙부 | 78.92% → 24.27% | 이 위치의 변화에도 모델이 민감하게 반응함 |
| 가장 큰 증가 | 가운데 왼쪽 | 78.92% → 79.70% | 처리 후 출력값이 소폭 증가함 |

실제 값에 따라 자동 생성하고 예시 수치를 하드코딩하지 마세요.

### 설명 일관성

기술 지표 대신 다음처럼 표현하세요.

```text
높음: 가림 방식을 바꿔도 주요 결과가 대체로 비슷함
보통: 일부 위치의 결과가 달라짐
낮음: 가림 방식에 따라 여러 위치의 결과 방향이나 순위가 달라짐
```

현재 사례처럼 안정성 판정이 낮으면 다음 경고를 강조하세요.

```text
가림 방식에 따라 일부 구역의 결과가 달라졌습니다.
따라서 특정 위치를 일관된 설명 위치로 단정하기 어렵습니다.
```

## 9. 용어 교체 규칙

의료진용 본문에서는 다음 용어를 교체하세요.

| 기존 기술 용어 | 의료진용 표현 |
|---|---|
| 모델 판단 | 모델 예측 |
| MCI 확률 | MCI 모델 출력값 |
| prediction probability | 모델 출력값 |
| 지지 근거 | 처리 후 출력값이 감소한 구역 |
| 억제 근거 | 처리 후 출력값이 증가한 구역 |
| 절대 민감도 | 처리에 민감하게 반응한 정도 |
| probability drop | 처리 후 모델 출력 변화 |
| CAM | 모델 반응 지도 |
| CAM 비율 | 설명 지도 내 상대 반응 비율 |
| Graph XAI | 영상 구역별 예측 변화 지도 |
| zero masking | 검은색으로 가림 |
| mean masking | 평균 밝기로 가림 |
| blur masking | 흐리게 처리 |
| sign agreement | 변화 방향 일치 정도 |
| stability | 설명 결과의 일관성 |

의료진용 본문에서 `Spearman`, `Kendall`, `Jaccard`, `SHA-256`, `Git commit`, `mock_mode`, `classes_`를 표시하지 마세요. 기술 부록으로 이동하세요.

## 12. Graph XAI 표현 개선

의료진용 보고서에서는 제목을 다음처럼 바꾸세요.

```text
영상 구역별 예측 변화 지도
```

그래프 설명:

```text
각 원은 영상의 한 구역을 나타냅니다.
원의 크기는 설명 지도에서의 상대 반응 정도를 나타냅니다.
색상은 해당 구역을 처리한 뒤 모델 출력값이 감소했는지 증가했는지를 나타냅니다.
연결선은 영상에서 서로 이웃한 구역임을 표시할 뿐 실제 신경 연결을 의미하지 않습니다.
```

색상만으로 의미를 구분하지 마세요.

- 색상과 `+`, `-` 기호 병기
- 색각 이상을 고려한 팔레트 사용
- 범례에 `질환/정상 색상이 아님` 표시
- 빨강을 `질환`, 파랑을 `정상`으로 표현하지 않기

## 13. 문서 디자인

- A4 기준 본문 10.5pt 이상
- 핵심 수치 16pt 이상
- 페이지당 표 1~2개 이하
- 영문·한국어 혼용 최소화
- 소수점은 본문에서 백분율 1~2자리
- 기술 부록에서만 원시 소수값 표시
- 제목·절 번호 순서를 실제 읽는 순서와 일치
- 1절 다음에 2절, 그다음 3절이 배치되도록 페이지 흐름 검사
- 표가 페이지 사이에서 부자연스럽게 분리되지 않게 처리
- 동일한 색상·기호 의미를 모든 페이지에서 유지
- 경고 문구를 지나치게 반복하지 말고 첫 페이지와 마지막 페이지에 명확히 배치
- `연구용` 워터마크 또는 머리말 유지

## 16. 테스트 요구사항

### 단위 테스트

- 기술 용어가 의료진용 본문에 노출되지 않는지 검사
- 출력값을 진단 확률로 표현하지 않는지 검사
- 예측 범주와 모델 출력값 연결 검사
- 안정성 수준별 쉬운 문구 생성 검사
- 양수·음수·0 변화 문구 검사
- 의료진용 표 최대 항목 수 검사
- 본문 백분율 반올림 검사
- 기술 부록에 원시 수치 보존 검사
- 보고서 모드별 페이지 구성 검사

### 통합 테스트

- `clinical_summary` PDF 생성
- `technical_full` PDF 생성
- `combined` PDF 생성
- 실제 모델 결과를 이용한 보고서 smoke test
- mock 결과의 명확한 표시
- UI 보고서 선택 기능
- PDF 다운로드

```text
질환 원인

신경 연결 확인
```

문맥과 무관한 단순 부분 문자열 검사가 오탐을 일으키면 허용 문장과 금지 문장을 구분하는 테스트 fixture를 사용하세요.

## 17. PDF 렌더링 검수

각 모드의 PDF를 생성한 뒤 모든 페이지를 PNG로 렌더링해 확인하세요.

검수 항목:

- 절 순서가 뒤바뀌지 않았는지
- 텍스트·표·그림이 잘리지 않았는지
- 글자 겹침이나 깨짐이 없는지
- 의료진용 본문 글씨가 충분히 큰지
- 그래프 축·범례가 한국어로 표시되는지
- 원본 MRI와 중첩 영상 방향이 같은지
- 색상과 부호 의미가 일치하는지
- 주요 결과가 첫 페이지에서 바로 보이는지
- 기술 정보가 본문을 방해하지 않는지

시각 검수에 실패하면 수정 후 다시 렌더링하세요.

## 18. 원본 파일 무결성

작업 후 다음을 실행하고 작업 전 기준선과 비교하세요.

```bash
git status --short
git diff --name-only
git diff --stat
```

원본 프로젝트 파일 변경이 발견되면 자동 복원하지 말고 경로와 차이를 보고한 후 중단하세요.

다음 명령은 실행하지 마세요.

```text
git reset
git reset --hard
git checkout --
git restore
git clean
git stash
git commit
git push
```
