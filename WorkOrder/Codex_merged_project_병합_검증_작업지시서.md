# Codex 작업지시서: `merged_project` 분할본 병합 및 검증

아래 작업을 현재 저장소에서 순서대로 수행하라.

## 1. 작업 환경

- 운영체제: Windows
- 셸: PowerShell
- 프로젝트 루트: `E:\Develop\CLIPtoXAI`
- 현재 존재하는 분할 폴더:
  - `merged_project-20260825T072246Z-1-001`
  - `merged_project-20260825T072246Z-1-002`
  - `merged_project-20260825T072246Z-1-003`
- 각 분할 폴더 내부에는 `merged_project` 폴더가 한 단계 더 들어 있을 가능성이 높다.

## 2. 최종 목표

세 분할 폴더의 내용을 다음 경로에 하나의 정상적인 프로젝트 구조로 병합한다.

```text
E:\Develop\CLIPtoXAI\merged_project
```

병합 후 다음 항목을 검증하고 보고한다.

1. 모델, 체크포인트, 예측 결과, Grad-CAM 결과가 누락되지 않았는지
2. `slices_multi`와 `mri_3d_cache`의 데이터가 세 분할본에서 모두 합쳐졌는지
3. 동일 상대 경로 또는 동일 파일명 충돌이 있는지
4. 충돌 파일의 내용이 같은지 다른지
5. 체크포인트가 PyTorch에서 읽을 수 있는지
6. CSV 파일이 정상적으로 파싱되고 필수 열과 행 개수를 확인할 수 있는지
7. 프로젝트 실행에 필요한 코드·설정·의존성 파일이 존재하는지

## 3. 절대 준수 사항

- 원본 분할 폴더 3개를 삭제하거나 이동하거나 이름을 변경하지 말 것.
- 기존 파일을 임의로 덮어쓰지 말 것.
- `Remove-Item`, `del`, `rm`, `git reset --hard`, `git clean` 등 삭제·초기화 명령을 사용하지 말 것.
- 먼저 읽기 전용으로 구조와 충돌을 검사할 것.
- 충돌 파일이 있으면 크기와 SHA-256 해시를 비교하고, 내용이 다르면 자동으로 어느 한쪽을 선택하지 말 것.
- 충돌이 발견되면 충돌 목록과 권장 처리 방법을 보고한 뒤 안전하게 중단할 것.
- 병합 대상 폴더가 이미 존재하면 내부 상태를 검사하고, 비어 있지 않다면 바로 복사하지 말 것.
- 모든 명령은 PowerShell에서 실행 가능한 형태로 작성할 것.
- `robocopy` 종료 코드는 `0~7`을 정상 범주, `8 이상`을 실패로 판정할 것.
- 데이터 규모가 크므로 파일 전체를 메모리에 동시에 적재하지 말 것.
- 의료영상 데이터나 모델 성능을 임상적으로 유효하다고 단정하지 말 것.

## 5. 작업 단계

### 단계 A. 사전 상태 점검

1. `E:\Develop\CLIPtoXAI`이 실제 작업 루트인지 확인한다.
2. `git status --short`와 현재 브랜치를 확인한다.
3. 세 분할 폴더가 모두 존재하는지 확인한다.
4. 각 분할 폴더 바로 아래에 `merged_project`가 존재하는지 확인한다.
5. 각 분할본의 전체 파일 수, 전체 크기, 확장자별 파일 수를 계산한다.
6. 예상과 다른 중첩 구조가 발견되면 실제 구조를 보고하고 경로를 자동 추정하지 말고 근거를 제시한다.

### 단계 B. 병합 전 충돌 검사

각 분할본의 `merged_project`를 기준으로 모든 파일의 상대 경로를 계산한다.

다음 두 종류를 별도로 검사한다.

1. 동일 상대 경로 충돌
2. 서로 다른 경로에 존재하는 동일 파일명

동일 상대 경로가 둘 이상이면 다음 정보를 출력한다.

- 분할본 번호
- 전체 경로
- 상대 경로
- 파일 크기
- 최종 수정 시각
- SHA-256
- 해시 동일 여부

내용이 다른 충돌이 하나라도 있으면 병합을 수행하지 말고 사용자 판단이 필요한 항목으로 보고한다.

### 단계 C. 안전한 병합

충돌이 없거나, 동일 상대 경로의 파일들이 SHA-256 기준으로 완전히 동일한 경우에만 진행한다.

1. `E:\Develop\CLIPtoXAI\merged_project`를 생성한다.
2. `001`, `002`, `003` 순서로 병합한다.
3. 파일 내용과 타임스탬프를 보존한다.
4. 동일 내용 파일은 불필요하게 다시 쓰지 않는다.
5. 각 분할본 처리 후 복사·건너뜀·실패 파일 수와 종료 코드를 기록한다.
6. 실패가 발생하면 다음 분할본으로 무조건 진행하지 말고 원인을 확인한다.

### 단계 D. 병합 결과 무결성 검증

병합 전 세 분할본의 고유 상대 경로 집합과 병합 후 상대 경로 집합을 비교한다.

다음을 검증한다.

- 누락 파일 수가 0인지
- 예상하지 않은 추가 파일이 있는지
- 원본과 병합본의 크기가 같은지
- 필요 시 SHA-256이 같은지
- 확장자별 파일 수가 일치하는지
- `slices_multi`의 PNG 개수
- `mri_3d_cache`의 NPY 개수
- ADNI 형식 파일명과 OASIS 형식 파일명이 모두 포함되는지

`list_folder`나 출력 제한처럼 조회 상한 때문에 보이는 수치를 실제 전체 개수로 오인하지 말고, 로컬 파일시스템에서 전체 개수를 직접 계산한다.

### 단계 F. 가벼운 로딩 테스트

현재 Python 환경과 설치된 패키지를 먼저 확인한다. 패키지가 없다는 이유로 시스템 전역에 임의 설치하지 말고 필요한 설치 명령만 제안한다.

1. CSV 파일
   - 헤더를 읽는다.
   - 행 개수와 열 이름을 출력한다.
   - 빈 파일, 파싱 오류, 중복 열 이름 여부를 검사한다.
   - 대용량 CSV는 필요한 열과 청크 방식으로 검사한다.
2. PyTorch 체크포인트
   - 가능하면 CPU 위치로만 읽는다.
   - 신뢰할 수 있는 로컬 파일이라는 전제에서 로드하되, 현재 PyTorch 버전에 맞는 안전한 옵션을 검토한다.
   - 체크포인트가 `state_dict`, 전체 모델, 또는 다른 딕셔너리 구조인지 키와 텐서 shape만 요약한다.
   - 전체 텐서 값을 출력하지 않는다.
3. NPY 파일
   - 전체 파일을 모두 로드하지 않는다.
   - 각 분할 구간에서 표본을 선택한다.
   - `numpy.load(..., mmap_mode='r', allow_pickle=False)`를 우선 사용한다.
   - shape, dtype, NaN/Inf 여부, 값 범위를 확인한다.
4. Grad-CAM
   - PNG 파일 개수와 이미지 크기 분포를 확인한다.
   - `gradcam_summary.csv`가 실제 이미지 파일과 연결되는지 검사한다.

- `README*`

- `pyproject.toml`
- `environment.yml`
- `setup.py`
- Python 실행 진입점
- 학습·추론·평가·Grad-CAM 생성 코드
- 모델 아키텍처 정의
- 클래스 순서와 라벨 매핑
- CLIP 텍스트 프롬프트 정의

체크포인트만 있고 모델 구조 코드가 없으면 체크포인트 단독으로 완전한 추론을 재현할 수 없을 가능성을 명시한다. `clip_best.pt`의 파일 크기가 매우 작다면 전체 CLIP 가중치가 아니라 분류 헤드 또는 일부 상태만 저장됐을 가능성을 실제 키 구조로 확인한다.

## 6. 구현 산출물

필요하면 다음 스크립트를 프로젝트 루트에 작성한다.

```text
scripts/inspect_merged_parts.ps1
scripts/merge_merged_parts.ps1
scripts/validate_merged_project.py
```

요구사항:

- 검사와 병합을 별도 스크립트로 분리한다.
- 기본 동작은 읽기 전용 검사여야 한다.
- 실제 병합에는 `-Execute` 같은 명시적 옵션을 요구한다.
- 경로를 하드코딩하기보다 프로젝트 루트를 매개변수로 받을 수 있게 한다.
- 실행 로그를 `artifacts/merge_validation/`에 저장한다.
- 로그에는 개인정보나 전체 의료영상 배열을 기록하지 않는다.
- 스크립트에는 사용법과 예상 종료 코드를 주석으로 작성한다.
